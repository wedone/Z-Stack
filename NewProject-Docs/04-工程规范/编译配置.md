# 编译配置

> 定义固件编译环境、工程文件、编译配置、关键预定义宏和编译产物。可执行步骤封装在 `firmware-build` skill 中。

## 1. 编译环境

| 工具 | 说明 |
|------|------|
| IAR Embedded Workbench for 8051 | 版本 8.10 或更高 |
| Z-Stack 3.0.2 | 已集成在项目仓库中 |
| Python 3 | 运行 hex2bin.py 转换工具、burn.py 一键烧录脚本 |

## 2. IAR 安装路径

默认安装路径（如不同请替换）：

```
C:\Program Files (x86)\IAR Systems\Embedded Workbench\common\bin\IarBuild.exe
```

> 注意：路径中**不含版本号**，直接是 `Embedded Workbench\common\bin`。

## 3. 工程文件

| 项 | 值 |
|----|----|
| 工程文件 | `Projects/zstack/HomeAutomation/HGZBSwitch/CC2530DB/HGZBSwitch.ewp` |
| 工作区文件 | `Projects/zstack/HomeAutomation/HGZBSwitch/CC2530DB/HGZBSwitch.eww` |
| 工程性质 | 独立工程，基于 Z-Stack 官方 SampleSwitch 修改（v1.0.0 起独立） |

> v1.0.0 起从官方 SampleSwitch 工程独立为 HGZBSwitch 工程，剥离了 Z-Stack 官方示例残留代码（UI / LCD / MT / Touchlink / GP 模块）。

## 4. 编译配置 (Configuration)

| 配置名 | 用途 | 当前状态 |
|--------|------|----------|
| CoordinatorEB | 协调器固件 | 不使用 |
| **RouterEB** | 路由器固件（无 OTA） | **当前唯一使用** |
| EndDeviceEB | 终端设备固件 | 不使用 |
| RouterEB - OTAClient | 路由器+OTA客户端 | 不使用（CC2530 256KB Flash 不支持 OTA） |
| EndDeviceEB - OTAClient | 终端+OTA客户端 | 不使用 |

> 当前使用 **RouterEB** 配置编译（非 OTA），设备角色为 Router。
>
> OTA 配置已弃用：CC2530 256KB Flash 空间不足以支持 Z-Stack Router 协议栈 + OTA Client。

## 5. CLI 编译命令

```powershell
$iar = "C:\Program Files (x86)\IAR Systems\Embedded Workbench\common\bin\IarBuild.exe"
& $iar "d:\vc\Z-Stack\Projects\zstack\HomeAutomation\HGZBSwitch\CC2530DB\HGZBSwitch.ewp" -build "RouterEB"
```

### 退出码判断

- 退出码 0 = 编译成功
- 非零 = 编译失败，需根据错误信息排查

## 6. 关键预定义宏

以下宏在 IAR 工程配置（`.ewp` 文件 RouterEB 配置的 `CCDefines` 节点）中定义，影响编译行为：

| 宏 | 说明 |
|----|------|
| `ZCL_REPORTING_DEVICE` | 启用 ZCL 属性上报功能（`zcl_SendReportCmd` 可用） |
| `ZG_BUILD_RTR_TYPE` | 设备类型为 Router |
| `CC2530` | 目标芯片 |
| `HAL_KEY=FALSE` | 禁用按键模块（避免 P2.0/P0.6 引脚冲突，v1.0.0 重构引入） |
| `HAL_LCD=FALSE` | 禁用 LCD 模块（设备无 LCD，hal_lcd.c 已从工程移除） |
| `HAL_ADC=FALSE` | 禁用 ADC 读取功能（hal_adc.c 保留编译，ZMain.c 调用 HalAdcCheckVdd 检查电压） |

> v1.0.0 重构后已移除 `OTA_CLIENT` 宏定义和相关代码。

## 7. 编译产物

产物路径：

```
Projects/zstack/HomeAutomation/HGZBSwitch/CC2530DB/RouterEB/Exe/
```

| 文件 | 说明 |
|------|------|
| `HGZBSwitch.hex` | Intel HEX 格式固件（IAR 输出，intel-extended 格式） |

> 编译后推荐直接使用 `firmware-burn` skill 或 `tools/burn.py` 一键烧录，自动完成 hex→bin 转换并烧录。

## 8. hal_key.c / hal_adc.c 保留编译说明

虽然通过宏禁用了 HAL_KEY 和 HAL_ADC 的功能，但 `hal_key.c` 和 `hal_adc.c` **必须保留编译**，原因：

| 文件 | 保留原因 |
|------|----------|
| `hal_key.c` | `OnBoard.c` 直接调用 `HalKeyConfig`，无条件编译保护。`HAL_KEY=FALSE` 时 `HalKeyInit` / `HalKeyConfig` / `HalKeyPoll` 编译为空函数，不再干扰 GPIO |
| `hal_adc.c` | `ZMain.c` 调用 `HalAdcCheckVdd` 检查电压，无条件编译保护。`HAL_ADC=FALSE` 时仅保留电压检查功能 |
| `hal_sleep.c` | `mac_mcu.c` 调用 `halSetMaxSleepLoopTime`，需保留空实现 |

> 协议栈核心文件直接调用这些 HAL 函数，无法通过宏完全排除。保留文件但通过宏禁用功能是 Z-Stack 的设计约束。

## 9. 常见编译错误

### 9.1 `Function "zcl_SendReportCmd" declared implicitly`

| 项 | 内容 |
|----|------|
| **原因** | 缺少 `ZCL_REPORTING_DEVICE` 宏定义 |
| **修复** | 在 `HGZBSwitch.ewp` 对应 configuration 的 `CCDefines` 中添加 `<state>ZCL_REPORTING_DEVICE</state>` |

### 9.2 编译成功但无 .hex 文件输出

| 项 | 内容 |
|----|------|
| **原因** | IAR 工程配置的 ExtraOutputFormat 设置错误（如输出 .sim 而非 .hex） |
| **修复** | 在 `HGZBSwitch.ewp` 中将对应配置的 `ExtraOutputFile` 设为 `HGZBSwitch.hex`，`ExtraOutputFormat` 设为 `23`（intel-extended） |
