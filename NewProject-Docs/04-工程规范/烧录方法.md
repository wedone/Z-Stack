# 烧录方法

> 定义固件烧录器硬件、烧录脚本、烧录命令和手动流程。可执行步骤封装在 `firmware-burn` skill 中。
>
> **本项目不使用 OTA Bootloader**：CC2530 256KB Flash 空间不足以支持 Z-Stack Router 协议栈 + OTA Client，采用 CC Debug 有线烧录方式。

## 1. 烧录器硬件

| 项 | 值 |
|----|-----|
| 硬件 | NodeMCU ESP8266 + CC2530 (CC Debug 接线) |
| 烧录器名称 | CCLoader |
| 默认地址 | `http://10.0.0.144` |
| API 端口 | 80 (HTTP) / 81 (SSE 实时事件) |
| 烧录接口 | CC Debug (D1=RESET, D2=DC, D6=DD) |
| 串口监控 | ESP8266 RX ← CC2530 P0_3 (UART0 TX) |
| 固件格式 | **仅接受 .bin**，.hex 会被拒绝 |

> 完整 API 文档: `curl.exe -s http://10.0.0.144/api/help`

## 2. 一键烧录（推荐）

封装 hex→bin 转换、上传、烧录、进度轮询为一条命令，无需手动分步操作。

### 烧录命令

```powershell
python d:\vc\Z-Stack\tools\burn.py
```

### 可选参数

```powershell
# 指定 CCLoader IP
python d:\vc\Z-Stack\tools\burn.py --ip 192.168.1.100

# 指定 hex 文件路径 (相对路径相对于项目根目录)
python d:\vc\Z-Stack\tools\burn.py --hex D:\path\to\firmware.hex

# 仅转换+上传, 不烧录 (用于先上传再择时烧录)
python d:\vc\Z-Stack\tools\burn.py --no-burn
```

### 依赖

```powershell
pip install requests
```

### 脚本流程

| 步骤 | 动作 | API |
|------|------|-----|
| 1 | 读取 IAR 编译输出的 `.hex`，内置 hex2bin 转换为 256KB `.bin`（填充 0xFF 到 CC2530F256 容量） | 本地 Python |
| 2 | 检查 CCLoader 设备就绪 | `GET /api/status` |
| 3 | 上传 `.bin` 到 LittleFS | `POST /api/upload` |
| 4 | 发起异步烧录，强制校验 | `POST /api/burn` |
| 5 | 轮询进度直到完成（约 90 秒） | `GET /api/status` |

> 默认参数：IP=10.0.0.144，hex=Projects/.../HGZBSwitch.hex（相对于项目根）。

## 3. 手动烧录流程（备用）

如需精细控制（如检查文件列表、删除旧文件、调试问题），可按以下步骤手动操作。

### 3.1 HEX 转 BIN

CCLoader API 仅接受 `.bin`，编译产出的 `.hex` 需先转换。

工具路径：`tools/hex2bin.py`

```powershell
# 单个固件转换（默认输出同名 .bin）
python d:\vc\Z-Stack\tools\hex2bin.py "d:\vc\Z-Stack\Projects\zstack\HomeAutomation\HGZBSwitch\CC2530DB\RouterEB\Exe\HGZBSwitch.hex"

# 指定输出路径
python d:\vc\Z-Stack\tools\hex2bin.py input.hex output.bin
```

> 默认填充到 256KB (0x40000)，缺失地址填 0xFF，适配 CC2530F256。

### 3.2 上传 BIN 到 CCLoader

```powershell
curl.exe -s -F "file=@HGZBSwitch.bin" http://10.0.0.144/api/upload
# 返回: {"success":true,"filename":"HGZBSwitch.bin","size":262144}
```

> 注意: PowerShell 中必须用 `curl.exe`，不能用 `curl`（后者是 Invoke-WebRequest 别名）。

### 3.3 发起烧录

```powershell
curl.exe -s -X POST "http://10.0.0.144/api/burn" -H "Content-Type: application/json" -d '{\"filename\":\"HGZBSwitch.bin\"}'
# 返回: {"success":true,"async":true,"task_id":1,"total_blocks":512}
```

> 烧录强制异步 + 强制校验，立即返回 task_id，后台执行。

### 3.4 轮询状态

```powershell
# 每2秒轮询一次
curl.exe -s http://10.0.0.144/api/status
# 烧录中: {"state":"burning","burn":{"percent":50,"current_block":256,"total_blocks":512,"done":false,"error":""}}
# 完成:   {"state":"idle","burn":{"percent":100,"done":true,"error":""}}
```

### 3.5 烧录后操作

```powershell
# 复位 CC2530
curl.exe -s -X POST http://10.0.0.144/api/reset

# 开始串口监控 (115200 baud)
curl.exe -s -X POST http://10.0.0.144/api/monitor -H "Content-Type: application/json" -d '{\"baud\":115200}'

# 获取串口日志（断点续传，since=时间戳）
curl.exe -s "http://10.0.0.144/api/monitor/buffer?since=0"

# 停止监控
curl.exe -s -X POST http://10.0.0.144/api/stop
```

## 4. API 端点速查

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | /api/help | 帮助文档 |
| GET | /api/status | 当前状态（烧录进度/监控/时间） |
| GET | /api/files | 列出已上传 BIN |
| POST | /api/upload | 上传 BIN（multipart, 字段 file） |
| DELETE | /api/files/{name} | 删除指定 BIN |
| POST | /api/burn | 烧录（强制异步+校验） |
| POST | /api/monitor | 开始监控 |
| GET | /api/monitor/buffer?since=N | 获取日志（断点续传） |
| POST | /api/stop | 停止监控 |
| POST | /api/reset | 复位 CC2530 |
| POST | /api/reboot | 重启 ESP8266 |

## 5. 常见问题

### Q1: 上传 .hex 报错 hex_not_supported？

API 仅接受 .bin，需先用 hex2bin.py 转换。浏览器端上传 .hex 会自动转换但 API 不会。

### Q2: 烧录失败？

1. 检查 D1/D2/D6 三根线是否接对
2. 确认 CC2530 GND 与 NodeMCU 共地
3. CC2530 需通电（3.3V）
4. 查看 `/api/status` 的 `burn.error` 字段

### Q3: PowerShell curl 报错？

PowerShell 的 `curl` 是 `Invoke-WebRequest` 别名，必须用 `curl.exe` 调用真正的 curl。

### Q4: 无法连接 CCLoader？

- 检查 ESP8266 是否通电并连入网络：`ping 10.0.0.144`
- 检查设备状态：`GET /api/status`，state 应为 `idle`
- 若 state 非 idle（上次烧录未完成），必要时重启 ESP8266

## 6. 烧录后验证

烧录完成后，按以下步骤验证：

1. **重新上电 CC2530 设备**（断电再上电，非 S1 复位）
2. 观察启动行为：
   - LED1 应开始 1Hz 慢闪（配网中）
   - 若已配网设备，应快速 rejoin 网络
3. z2m 检查设备状态：
   - 设备应在线
   - `swBuildId` 应显示新版本号
   - `dateCode` 应显示当日日期
4. 按 CHANGELOG 中的"验证要点"测试新功能
