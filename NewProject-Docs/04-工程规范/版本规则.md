# 版本规则

> 定义固件版本号格式、变更规则、发版更新清单。发版（修复BUG或增减功能后编译烧录）时必须严格遵循。

## 1. 版本号格式

采用语义化版本 `vX.Y.Z`：

| 版本段 | 何时递增 | 示例 |
|--------|----------|------|
| **主版本号 (X)** | 重大架构变更、里程碑、不兼容修改 | v0 → v1（从 SampleSwitch 改为自定义架构） |
| **次版本号 (Y)** | 新增功能、向后兼容 | v0.1 → v0.2（新增断电记忆功能） |
| **修订号 (Z)** | BUG 修复、小调整 | v0.1.0 → v0.1.1（修复触摸检测BUG） |

> v0.x.x 表示项目处于初始开发阶段，功能尚未完全稳定。

## 2. ZCL 版本属性

固件版本通过以下 ZCL 属性标识，定义在 `zcl_samplesw_data.c`：

| 属性 | ZCL Cluster | ZCL Attribute | 变量名 | 格式 |
|------|-------------|---------------|--------|------|
| SwBuildId | genBasic (0x0000) | ATTRID_BASIC_SW_BUILD_ID (0x4000) | `zclSampleSw_SwBuildId` | `型号-VX.Y.Z` |
| DateCode | genBasic (0x0000) | ATTRID_BASIC_DATE_CODE (0x0005) | `zclSampleSw_DateCode` | `YYYYMMDD` |
| HWVersion | genBasic (0x0000) | ATTRID_BASIC_HW_VERSION (0x0003) | `zclSampleSw_HWRevision` | `uint8` (0~255) |
| ManufacturerName | genBasic (0x0000) | ATTRID_BASIC_MANUFACTURER_NAME (0x0004) | `zclSampleSw_ManufacturerName` | ZCL 字符串 (≤32字符) |

z2m 通过读取 genBasic Cluster 查看固件版本和编译日期。

## 3. SwBuildId 格式

- **格式**：`HA-SPA4C1-VX.Y.Z`（型号 `HA-SPA4C1` + 分隔符 `-` + 版本号 `VX.Y.Z`）
- **长度限制**：**字符串内容最多 16 字符**（不含长度前缀字节），加上 1 字节长度前缀共 17 字节
- **超长风险**：超过 16 字符会导致 MTU 超限，z2m 读取固件 ID 时丢失

示例：

```c
// 正确: 16 个字符（HA-SPA4C1-V1.0.9）
const uint8 zclSampleSw_SwBuildId[] = { 16, 'H','A','-','S','P','A','4','C','1','-','V','1','.','0','.','9' };

// 错误: 17 个字符（HA-SPA4C1-V1.0.10），超长
const uint8 zclSampleSw_SwBuildId[] = { 17, 'H','A','-','S','P','A','4','C','1','-','V','1','.','0','.','1','0' };
```

> **注意**：版本号到 v1.0.9 时正好 16 字符。后续若版本号位数增加（如 v1.0.10），需缩短型号前缀（如 `SPA4C1-V1.0.10`）以保持在 16 字符内。

## 4. DateCode 格式

- **格式**：`YYYYMMDD`，8 字节字符串
- **必须**对应实际编译/发版日期，**不得沿用 Z-Stack SampleSwitch 默认值 `20060831`**
- 同一天多次编译可共用同一 DateCode
- 每次发版（非调试编译）时更新

示例：

```c
const uint8 zclSampleSw_DateCode[] = { 8, '2','0','2','6','0','7','2','8' };
```

## 5. ZCL 字符串格式

ZCL 字符串以**长度前缀字节**开头，后跟字符数据，长度必须等于实际字符数（不含 `\0` 终止符）：

```c
// 正确: 长度=6, 6 个字符
const uint8 zclSampleSw_ManufacturerName[] = { 6, 'L','i','n','x','e','e' };

// 错误: 长度与字符数不符
const uint8 zclSampleSw_ManufacturerName[] = { 8, 'L','i','n','x','e','e' };  // 长度 8 但只有 6 字符
```

> Z-Stack SampleSwitch 原始代码用空格填充到 16 字节，导致 z2m 显示 `20260728        `（带尾部空格）。本项目已修正为精确长度。

## 6. 发版更新清单（四文件同步）

**修复 BUG 或增减功能后编译烧录即为一次发版，必须递增版本号并同步更新以下四个文件：**

| 序号 | 文件 | 更新内容 |
|------|------|----------|
| 1 | `zcl_samplesw_data.c` | `zclSampleSw_SwBuildId` 改为新版本号 (`HA-SPA4C1-VX.Y.Z`) + `zclSampleSw_DateCode` 改为当日日期 (`YYYYMMDD`)；硬件版本变更时同步更新 `SAMPLESW_HWVERSION` |
| 2 | `CHANGELOG.md` | 新增版本条目，按 `## vX.Y.Z - YYYY-MM-DD` 格式，包含 Added / Fixed / Changed 章节 |
| 3 | `项目文档索引.md` | 更新「项目基本信息」章节中的"当前版本"字段 |
| 4 | `项目进展.md` | 更新"当前状态"中的版本号 + 添加版本里程碑和测试要点 |

### CHANGELOG 条目格式

```markdown
## vX.Y.Z - YYYY-MM-DD

简述本版本主要内容。

### Added
- 新功能描述 (commit hash)

### Fixed
- 修复的BUG描述 (commit hash)

### Changed
- 变更描述 (commit hash)
```

## 7. 发版流程

1. 修改代码完成功能或 BUG 修复
2. 按本文件第 6 节更新四文件
3. 触发 `firmware-build` skill 编译 RouterEB 配置
4. 触发 `firmware-burn` skill 烧录到设备
5. 按 CHANGELOG 中的"验证要点"测试功能
6. 验证通过后提交代码
