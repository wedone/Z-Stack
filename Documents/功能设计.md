### 基于 Z-Stack 3.0.2 SampleSwitch 的修改策略

> **项目背景**: 当前项目基于 Z-Stack 3.0.2 官方示例 `Projects/zstack/HomeAutomation/SampleSwitch` 修改开发。官方 SampleSwitch 是单路 HA 开关示例 (Router 角色, ZCL_HA_DEVICEID_ON_OFF_SWITCH), 不含 LED/触摸/断电记忆等外设功能。早期曾尝试基于 DIYRuZ_RT 框架, 因与需求差异过大已弃用。

| SampleSwitch 原版 | 修改目标 | 状态 |
|-------------------|----------|------|
| 1 个开关 Endpoint (EP1, genOnOff) | 4 个开关 Endpoint (EP1-4) + 4 个 genAnalogInput 输入状态 (EP5-8) | ✅ 完成 |
| 默认 ModelId ("TI0001" 等) | 借壳 HGZB-4S (`LXN-4S27LX1.0`), Z2M 内置匹配 | ✅ 完成 |
| 单路按键 (HAL_KEY) | 4 路 WTC6106BSI 触摸 (100ms 轮询) + 1 路 S1 配网/复位按键 | ✅ 完成 |
| 无 LED 控制 | 增加 4 路 LED 反逻辑控制 (继电器 OFF → LED 亮) | ✅ 完成 |
| 无断电记忆 | NV 存储 + 4 路独立 startUpOnOff (NV ID 0x0F10/0x0F12) | ✅ 完成 (v0.2.0/v0.2.2) |
| 默认无周期上报 | 入网立即上报 + 30 秒周期上报 (启用 ZCL_REPORTING_DEVICE 宏) | ✅ 完成 (v0.2.1) |
| Binding 支持 (genGroups) | 保留 genGroups + 待配置 Z2M Binding | ❌ 待实现 |
| Router 角色 | 保留 (RTR_NWK=1, MAX_RTG_ENTRIES=40 等) | ✅ 完成 |
| OTA 升级 | 弃用 (聚焦日常常用功能, 不实现 OTA) | ❌ 已弃用 |

## 本地控制

| 触发源 | 动作 | 结果 |
|--------|------|------|
| 触摸按键 1 | 按下 | 切换第1路继电器状态 + LED 反相 + ZCL上报 |
| 触摸按键 2 | 按下 | 切换第2路继电器状态 + LED 反相 + ZCL上报 |
| 触摸按键 3 | 按下 | 切换第3路继电器状态 + LED 反相 + ZCL上报 |
| 触摸按键 4 | 按下 | 切换第4路继电器状态 + LED 反相 + ZCL上报 |
| S1 短按 | — | 配网（HAL层处理） |
| S1 长按5秒 | — | 工厂复位 `bdb_resetLocalAction()` |

> **触摸信号**: WTC6106BSI 输出持续高低电平，触摸时 OUT 拉低，松开恢复高电平。100ms 轮询检测下降沿触发翻转，软件防抖（连续2次=200ms确认）。

| 命令 | 动作 | 结果 |
|------|------|------|
| OnOff: On (EP1) | 第1路开 | 继电器吸合 + LED 灭 + ZCL上报 |
| OnOff: Off (EP1) | 第1路关 | 继电器断开 + LED 亮 + ZCL上报 |

## 状态上报与同步

### 触发方式

| 触发场景 | 上报方式 | 函数 |
|----------|----------|------|
| 本地触摸操作 | 立即上报单路 | `zclSampleSw_ReportOnOffState(idx)` |
| 远程 ZCL 命令处理后 | 立即上报单路 | `zclSampleSw_ReportOnOffState(idx)` |
| 设备入网 (DEV_ROUTER) | 立即上报 4 路 | `zclSampleSw_ReportAllOnOffState()` (v0.2.1+) |
| 周期性 (30秒) | 上报 4 路 | `zclSampleSw_ReportAllOnOffState()` (v0.2.1+) |
| Coordinator Read 请求 | ZCL 自动响应 | Z-Stack 内置 |

### 状态同步机制 (v0.2.1 修复 BUG-007/BUG-008)

**双机制保证 Z2M 状态一致性**：
1. **入网立即上报**: 设备 ZDO 状态变为 `DEV_ROUTER` 时, 调度 `SAMPLESW_STATE_REPORT_EVT` 事件立即上报 4 路状态, 修复断电恢复后 Z2M 不同步 (BUG-007)
2. **周期性上报**: 每 30 秒 (`STATE_REPORT_INTERVAL_MS = 30000ms`) 触发一次 4 路状态上报, 修复信号不好时单次上报丢失导致长期不同步 (BUG-008)

详见 [Zigbee设备模型.md](Zigbee设备模型.md) 状态同步机制章节。

## Router 路由功能

Z-Stack 3.0.2 官方 SampleSwitch 示例默认以 **Router（路由器）** 角色加入 Zigbee 网络。本设备保留该功能，使 4 路智能开关同时具备 **Zigbee 信号中继** 能力。

| 优势 | 说明 |
|------|------|
| 扩展网络覆盖 | 开关安装位置通常分布在房间各处 |
| 增强网络稳定性 | 为终端设备提供多条路由路径 |
| 无需额外设备 | 不增加硬件成本 |
| 常供电优势 | 墙壁开关长期通电，不会因断电导致路由表丢失 |

主要配置参数：
```c
#define ZDO_COORDINATOR 0    // 不是协调器
#define RTR_NWK           1    // 启用路由功能
#define MAX_RTG_ENTRIES   40   // 路由表条目数
#define MAX_RREQ_ENTRIES  8    // 路由请求条目数
#define MAX_NEIGHBOR_ENTRIES 16 // 邻居表条目数
```

## 断电记忆功能 (v0.2.0+, v0.2.2 修复 4 路独立配置)

### 功能说明

断电后再次上电时，按每路独立的 `startUpOnOff` 配置恢复开关状态：

| 配置值 | 名称 | 行为 |
|--------|------|------|
| 0x00 | OFF | 上电后该路为 OFF |
| 0x01 | ON | 上电后该路为 ON |
| 0x02 | TOGGLE | 上电后翻转断电前状态 |
| 0xFF | PREVIOUS | 恢复断电前状态 (默认) |

### NV 存储设计

| NV ID | 大小 | 内容 | 说明 |
|-------|------|------|------|
| 0x0F10 | 4 字节 | 4 路继电器状态 | 断电前状态, 用于 PREVIOUS/TOGGLE 恢复 |
| 0x0F12 | 4 字节 | 4 路独立 startUpOnOff 配置 | v0.2.2 起 (旧 ID 0x0F11 已废弃) |

> **避坑**: v0.2.0/v0.2.1 误用 4 路共用单变量 `zclSampleSw_StartUpOnOff`, Z2M 写入 4 路独立配置时互相覆盖 (BUG-009)。v0.2.2 改为 `uint8[4]` 数组, 4 EP 属性表分别指向独立元素。

### 实现要点

```c
// 4 路独立 startUpOnOff 配置
uint8 zclSampleSw_StartUpOnOff[SAMPLESW_NUM_RELAYS] = {STARTUP_ONOFF_PREVIOUS, ...};

// 4 个 EP 属性表分别指向独立元素
zclSampleSw_RelayAttrs_ep1[] = { ..., &zclSampleSw_StartUpOnOff[0] };
// ... ep2/ep3/ep4 类似

// 上电恢复: 按每路独立配置恢复
for (i = 0; i < SAMPLESW_NUM_RELAYS; i++) {
    switch (zclSampleSw_StartUpOnOff[i]) {
        case STARTUP_ONOFF_OFF:     zclSampleSw_RelayState[i] = FALSE; break;
        case STARTUP_ONOFF_ON:      zclSampleSw_RelayState[i] = TRUE;  break;
        case STARTUP_ONOFF_TOGGLE:  zclSampleSw_RelayState[i] = !savedRelayState[i]; break;
        case STARTUP_ONOFF_PREVIOUS:
        default:                    zclSampleSw_RelayState[i] = savedRelayState[i]; break;
    }
}
```

### 触发保存时机

- **继电器状态**: 100ms 轮询检测变化, 5 秒延迟写入 NV (避免频繁写入 Flash)
- **startUpOnOff 配置**: 100ms 轮询检测 Z2M 远程修改, 5 秒延迟写入 NV

| 注意点 | 说明 |
|--------|------|
| Flash 擦写寿命 | CC2530 Flash 约 10 万次擦写, 延迟写入策略降低频率 |
| 写入延迟 | Flash 写入期间设备可能无响应, 用定时器延迟写入避免阻塞 |
| 首次上电 | 无 NV 数据时默认 4 路全 OFF, startUpOnOff 默认 PREVIOUS |
| NV ID 变更 | v0.2.2 起 NV ID 0x0F11 (1字节) → 0x0F12 (4字节), 旧项遗留不使用 |

## 开关同步功能 (Binding)（待实现）

通过 Zigbee Binding 机制 + genGroups Cluster 实现。Z2M 端配置 Binding，设备端支持 genGroups Cluster 即可。

**设备端需要**:
1. genGroups Cluster (0x0004) — 已在 InClusterList 中
2. BDB_COMMISSIONING_MODE_FINDING_BINDING — 已启用
3. Binding 响应 — Z-Stack 3.0 自动处理

**工作原理**:
```
┌──────────┐   Binding Table   ┌──────────┐
│  开关 A   │◄────────────────►│  开关 B   │
│ EP1: OnOff│   直连通信        │ EP1: OnOff│
└──────────┘  (不经协调器)     └──────────┘
```

>
> 以下内容仅作为历史参考, 不再实现。

### CC2530F256 Flash 分区现状

| 区域 | 页范围 | 大小 | 说明 |
|------|--------|------|------|
| Boot Loader | 0~3 | 8KB | Serial Boot Loader |
| 用户代码 | 4~120 | ~234KB | 应用程序 + Z-Stack |
| NV 存储 | 121~126 | 12KB | 6 页 NV |
| Lock Bits | 127 | 2KB | Flash 锁定位 |

### OTA 分区规划

| 区域 | 页范围 | 大小 | 说明 |
|------|--------|------|------|
| Boot Loader | 0~3 | 8KB | 需升级为 OTA Boot Loader |
| 用户代码 | 4~60 | ~114KB | 当前固件（含 Z-Stack 约80~100KB） |
| OTA Image | 61~120 | ~120KB | OTA 下载区（预留） |
| NV 存储 | 121~126 | 12KB | 不变 |

2. OTA Cluster 注册: Endpoint 1 添加 `ZCL_CLUSTER_ID_OTA` (0x0019)
